## 2. 架构

```
src/scene/
  SpaceScene.ts              引擎：网格/线框球/相机/雾/装饰/帧循环（captain 所有，别动）
  profiles/
    types.ts                 BodyProfile 契约（别动）
    math.ts                  通用数学件：gauss / well / doubleWell / rim / funnel …（别动，缺什么写自己文件里）
    index.ts                 id -> profile 注册表（别动）
    sol.ts       ┐
    sirius-b.ts  │
    crab-pulsar.ts│  6 个天体各一个文件 —— 每个 agent 只拥有其中一个
    cygnus-x-1.ts│
    procyon-b.ts │
    betelgeuse.ts┘
```

`BodyProfile` 的字段（详见 `types.ts`）：

| 字段 | 作用 |
| --- | --- |
| `surface(x, z, ctx)` | **形变面**：返回该点世界高度 y。0 = 未扰动平面，负 = 向下凹陷。每帧对每个网格顶点求值（约 1 万个），必须廉价 |
| `grid` | 网格采样：`half` 覆盖范围、`stepNear` 原点附近步长、`stepGrow` 步长增长率 |
| `camera` | 机位：`polarDeg`（自 +Y 轴量起，90=平视）、`radius`、`azimuthDeg`、`targetY`、`fov` |
| `sphere` | 球半径/球心高度/经纬分段/自转/明暗/填色/线框色/姿态 |
| `style` | 底色、网格线色与不透明度、雾近远（决定地平线位置） |
| `decor` | 尘埃点、贴地小方块、螺旋吸入粒子的强度 |

**切换天体时**引擎会把 from/to 两个 profile 的 `surface` 按 easeOutCubic 线性混合，
其余标量同步插值；`grid` 采样若不同则重建几何并交叉淡入。
`surface` 里可以读 `ctx.r`（= hypot(x,z)，引擎已算好）与 `ctx.t`（秒，用于缓慢呼吸）。

## 3. 评测工具（唯一的客观依据）

前置：dev server 必须在跑。没跑就先起一个（后台）：

```bash
cd /Users/liuzh/Documents/ZCode/star_web
curl -s -o /dev/null http://127.0.0.1:5199/ || npx vite --port 5199 --strictPort &
```

跑评测：

```bash
node scripts/refcmp.mjs <你的天体 id>      # 例：node scripts/refcmp.mjs sol
```

它会：打开无头 Chromium → 点左栏对应卡片 → 等动画稳定 → 截取**视口**（852x689）
→ 与参考图裁出的同区域逐像素比对，然后写出：

| 产物 | 内容 |
| --- | --- |
| `shots/cur/<id>.png` | 本次的视口截图 |
| `shots/cmp/<id>.png` | **三联图**：左=参考图视口，中=当前视口，右=差异叠加（**红=只有参考有墨，绿=只有当前有墨，深灰=两者都有**） |
| `shots/cmp/<id>.json` | 全部量化指标 |

**怎么看三联图（最重要）**：
- 右图出现**成对的平行红绿线** = 网格线的位置/相位错位 → 调 `grid.stepNear`、相机或形变面。
- 右图**大片纯红** = 参考图有结构而你没有 → 形状/雾/相机没做到位。
- 右图**大片纯绿** = 你多了参考图没有的东西（多余起伏、多余粒子、线太粗太密）。
- 球体轮廓出现**红绿双影** = 球的位置或直径不对。

**指标含义**：

| 指标 | 含义 | 怎么用 |
| --- | --- | --- |
| `coarseIou` | 4x4 下采样后的「结构位置」IoU（0..1） | **主指标**。1px 宽的线错开 1~2px 逐像素 IoU 就归零，所以用粗粒度看结构有没有对上 |
| `mad` | 灰度平均绝对差（0..255） | 整体墨量/浓淡是否接近 |
| `iou` | 逐像素墨迹 IoU | 辅助，对线宽与相位极敏感，别只盯它 |
| `inkRef` / `inkCur` | 参考 / 当前的墨迹像素占比 | `inkCur` 明显大于 `inkRef` = 你的线太多太重 |
| `rowInk[24]` / `colInk[24]` | 按 24 条行/列带统计的墨迹占比 | 打印出的 ASCII 条形图能直接看出结构在竖直/水平方向对不对齐 |

**注意**：场景本身在动（网格呼吸、球自转、尘埃漂移），所以 `mad` 不可能为 0，
每次跑数字也会有 ±0.3 的抖动。看趋势，不要 chasing 噪声。

## 5. 参考图里每个天体长什么样（逐图实测）

坐标一律用「视口归一化」：x 从左 0 到右 1，y 从上 0 到下 1，视口 852x689 CSS px。

### SOL —— `reference_images/reference.png`
- 线框球：直径 ≈ 250px（视口宽的 29%），球心 ≈ (50%, 42%)。
- 网格是一块平整的平面，视角中等俯视，地平线在 y ≈ 25%~30% 处淡出。
- 球底压进一个**中等深度、边缘平缓**的凹坑；网格线从两侧扫下来在球底汇成一圈
  明显的「编篮」结构。
- 近场格子宽 ≈ 55px。线细（≈1.5px），深灰绿。**远场是干净的平面，没有任何丘陵/沙丘起伏。**
- 散落少量深色小方块、细小的「+」标记和稀疏尘点。

### SIRIUS B —— `336e4fce-69a2-4664-855d-096403d6995a.png`
- 线框球：直径 ≈ 115px（13.5%），球心 ≈ (50%, 42%)，明显比 SOL 小。
- 平面整体呈**大范围缓拱**：远处先微微隆起再落向地平线（y ≈ 25%）。
- 球下方是一个**收敛得很急的火山口**：网格线在球体附近被强烈「捏」进去，
  球看起来是卡在坑颈里，而不是浮在浅碗上。
- 近场格子宽 ≈ 50px。

### CRAB PULSAR —— `7810ec85-27d1-4bbd-aec0-a87cde4174e6.png`
- **球不在平面高度上**：整个平面塌缩成一个**深漏斗（双曲面喇叭）**。
- 漏斗口很宽：在 y ≈ 30% 处横跨约 x 25%~75%；井壁向下急剧收拢。
- 小球（直径 ≈ 55px）沉在漏斗**深处**，球心 ≈ (50%, 76%)。
- 漏斗尖端继续向下延伸到 y ≈ 88% 才收束。
- 漏斗上方的平面宽阔、平缓、略微上拱；下方画面基本是空白。

### CYGNUS X-1 —— `178c54d2-bad5-4f2a-8011-832aa1e5a7c1.png`
- **最细最深的针管漏斗**：上方平面几乎平坦（只有极轻微的鼓包），
  从 y ≈ 35% 开始收成一个细长喇叭，一路扎到 y ≈ 82%。
- 蝴蝶结状的小黑球（直径 ≈ 28px）在漏斗尖端，球心 ≈ (50%, 80%)。
- 井壁由大量近乎垂直的长线汇聚而成（细密线条是该天体的关键特征）。
- 漏斗以外的平面**非常稀疏、极淡**，几乎没有横向线。

### PROCYON B —— `28c94a5d-f267-4881-96c8-976135dd83eb.png`
- 线框球：直径 ≈ 160px（19%），球心 ≈ **(50%, 63%)** —— 比 SOL/SIRIUS 明显更低。

## 6. 已知的坑

1. **网格线的粗细改不了**：three.js 的 `LineBasicMaterial.linewidth` 在 WebGL 下被忽略，
   线永远是 1 个设备像素（devicePixelRatio=2 时 = 1 个 CSS 像素）。参考图的线约 1.5px，
   如果这成为你的主要障碍，**给 captain 发消息**要求在引擎里加粗线方案，不要自己改引擎。
2. **参考图是整屏截图**，工具会自动裁出视口；视口上的文字叠加层（大标题、右上读数、
   左下 SINGULARITY ENGINE）已被遮罩排除在评分之外，**不用管它们**。
3. **不要靠"加雾/调透明度"刷 `mad`**：`inkCur` 掉到远低于 `inkRef` 说明你在把结构藏掉，
   这不会提升 `coarseIou`，评审也不会通过。
4. **网格顶点预算 40000**：`half / stepNear / stepGrow` 太密会触发引擎告警并掉帧。
   当前 105x105 ≈ 1.1 万顶点是安全区。
5. 改完文件 Vite 会自动热更新，下一次 `refcmp` 会重新加载页面，不需要手动重启 dev server。

## 7. 迭代节奏建议

1. 先跑一次 `node scripts/refcmp.mjs <id>` 拿到起点三联图。
2. 读 `shots/cmp/<id>.png`，把差异归类（球的位置/直径？井的形状？网格尺度？地平线？）。
3. 一次只改**一类**参数，重跑，看 `coarseIou` 是否上升。
4. 收敛后跑 `npx tsc --noEmit` 确认类型没坏。
5. 在提交说明里写清楚：改了哪些参数、`coarseIou`/`mad` 从多少到多少、三联图还剩什么差异。

## 8. 2026-09-29 全量对齐结果（单人完成 6 天体）

本轮把 6 个天体全部对齐到了参考图形态，要点记录：

**引擎能力扩展（SpaceScene.ts / types.ts）**
- `BodyProfile.gridFade?: { maxR, softness }`：网格顶点亮度按半径淡出。
  实现走顶点色（`mix(纸底色, 墨色, fade)`，材质色恒白）——WebGL 线没有逐顶点 alpha，
  把线颜色混到纸底色即视觉消失。已修复混合方向 bug（morph 完成时必须取 to 档案的 fade）。
- 相机关键发现：参考图全部是**长焦（fov 34）+ 沿网格对角线看（azimuth 45°，菱形格子）**。
- 「深井=无限平面」是误区：crab/cygnus 的参考图是**有限圆盘**（草帽檐 / 小杯口），
  靠 `grid` 缩到盘内 + `gridFade` 圆角实现，盘外是纸底。

**各天体最终 coarseIou**（基线→现值）：sol 0.44→0.417（结构重做：菱形网格+嵌碗，
旧 0.44 是方位角错误状态）、sirius-b 0.277→0.423、crab-pulsar 0.187→0.488、
cygnus-x-1 0.126→0.312、procyon-b 0.344→0.365、betelgeuse 0.292→0.303。
平均 0.278→0.383，平均 mad 21.5→16.6。

**已知的残余差距**（平面型四天体共用）：参考图为手绘插画，远场线条呈波浪状散布在
21-40% 一整条带里；真实透视相机（俯仰 ~9.5°）必然把远处线挤成 29-33% 的一条实心带。
sol 用极角 80.5° + targetY -0.85 已把带位置对齐；procyon 用远场沙丘带补足了上半幅结构。
